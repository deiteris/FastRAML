# raml-codegen

Generate source code from a RAML 1.0 definition, through the fastRAML **effective
tree**.

```bash
raml-codegen python api.raml -o out/
```

## What it reads

Not the RAML. The [effective tree](../../docs/16-graph.md) — the JSON that
`fastraml tree` writes — which is the same document with nine passes of RAML
already run:

| | who did it |
|---|---|
| `!include` resolution, `uses:` namespacing | P1 |
| type expressions — `(A\|B)[]`, nested arrays | P6/P7 |
| inheritance merge, facet narrowing, multiple inheritance | P9 |
| traits, resource types, optional-method filtering | P4a |
| overlays and extensions | P3 |
| security scheme binding, OAuth scope narrowing | P5 |
| default `mediaType`, baseUri parameter propagation | P4/P6 |

What arrives is three constructs and nothing else:

```
{"$ref": <address>}                            a link — look the target up
{"type": "recursive", "head": {"$ref": ...}}   repeats here, do not expand
anything else                                  containment — descend
```

A consumer descends containment, follows a link when it chooses to, and stops at
a recursion marker. It keeps no ancestor set. `raml_codegen/reader.py` is that,
and is the only module here that knows what the JSON means.

`raml_codegen/tree.py` is the typed declaration of the contract, generated by
`python -m fastraml.views.bindings python`. **Never edit it** — the parser's own
gate fails when it is stale.

## The `python` target

A typed `httpx` client, in the shape
[openapi-python-client](https://github.com/openapi-generators/openapi-python-client)
established, with stdlib dataclasses in place of attrs:

```
out/<package>/
  __init__.py  client.py  errors.py  types.py  security.py  py.typed
  models/      one module per declared type, @dataclass(slots=True)
  api/         one module per endpoint and method
  pyproject.toml  README.md
```

The generated package depends on `httpx` and nothing else. **So does this one**:
generation runs no subprocess and shells out to no formatter. An earlier version
ran `ruff` over its own output, which made what it produced a function of the
installed ruff version — and worse, silently produced unsorted and unused
imports on a machine where ruff was missing, because `check --fix-only` and "no
such module" both exit 1. What a module imports is knowable from its own plan.

```python
from bookstore_api.client import Client
from bookstore_api.api.books import get_books

client = Client(base_url='https://acme.books.example.com/v2')
books = get_books.sync(client=client, limit=10)
```

Each endpoint module exposes four entry points: `sync_detailed` and
`asyncio_detailed` return a `Response[T]` carrying the status code, the raw
content and the parsed body; `sync` and `asyncio` return the parsed body alone.

### How a shape becomes a type

| tree | Python |
|---|---|
| `string`, or with `enum:` | `str`, `Literal['a', 'b']` |
| `integer`, `number` | `int`, `float` |
| `boolean` | `bool` |
| `datetime`, `datetime-only` | `datetime.datetime` |
| `date-only`, `time-only` | `datetime.date`, `datetime.time` |
| `file` | `File` |
| `nil`, `null` | `None` |
| `any` | `Any` |
| `object` with properties | a generated dataclass |
| `object` without | `dict[str, Any]` |
| `array` | `list[T]` |
| `union` | `A \| B`, with a converter (below) |
| `json` | its `projection` — a `json` shape is how the type arrived, not what it is |
| a recursion marker | the type it repeats, by name |

### Two that are not one-liners

**An inlined supertype is its supertype — but only if it adds nothing.** The
effective view inlines a supertype wherever it is not referenced by name, so
`body: Book` arrives as an anonymous object carrying every one of Book's
properties. Read literally that generates `PostBooksBody`, a duplicate of `Book`
under a name the author never wrote, in every operation that mentions the type.
A shape that inherits exactly one declaration *and names exactly its properties*
is that declaration.

The test is about properties, not names, so it answers both halves at once:

| document | generated |
|---|---|
| `body: Book` | nothing — it *is* `Book` |
| `body: Book` **plus** `draft` | `PostBooksBody`, with `draft`, `title`, `isbn` |
| `Magazine: type: Publication` **plus** `issue` | `Magazine`, with `issue`, `kind`, `title` |

A declared subtype and an extended inline body take the same route; the only
difference is that the first already has a name.

**Every model is flat.** `Magazine` is not a subclass of `Publication`. The tree
merged the hierarchy before this package saw it, and RAML inheritance has no
Python subclass form anyway: `type: [A, B]` has no MRO, and a subtype that
*narrows* a property's type has no legal override. A rule with those exceptions
is worse than one rule.

What flattening costs is `isinstance`, so the part of a hierarchy a caller
actually switches on survives as a constant:

```python
from bookstore_api.models import magazine

if payload.get(*magazine.DISCRIMINATOR[:1]) == magazine.DISCRIMINATOR[1]:
    ...
#: magazine.DISCRIMINATOR == ('kind', 'monthly')
```

It is emitted only where the document *states* the value. RAML defaults an
unstated `discriminatorValue:` to the type name, and applying that default here
would be this package holding a rule of the language.

**A union does not know its own type until it has a value**, so identity
conversion is wrong in both directions. Going out, `to_json` looks at the value.
Coming in, nothing can look at the value except its shape, so it is told apart by
what the *document* says about its members, in this order:

1. a `discriminator:` and the member's `discriminatorValue:` — the author saying
   outright how to recognise one;
2. a required property no sibling requires — `isbn` is a `Book`, `rating` is a
   `Review`;
3. whether it is a list or an object, which no two of those are each other.

An unstated `discriminatorValue:` is **not** defaulted to the type name, though
RAML says it is: that is a rule of the language, and holding one here is what
this package may not do.

Where the document distinguishes nothing — two array members, say — the value is
handed back as it arrived. A `ShelfSlot` that is really a `Money` would be worse
than an undecoded list. **The annotation still carries every member**, because
the spelling is what the document says and narrowing it to describe a limitation
of this generator would throw away what the author wrote.

### What an inline type is called

A body declared by name — `type: Book` — is that type; nothing is generated.
A body declared inline has no name, and one has to come from somewhere:

| | example |
|---|---|
| 1. `displayName:`, if the author wrote one | `displayName: Existing order` → `ExistingOrder` |
| 2. where it sits, for a body or a response | `POST /orders` → `PostOrdersBody`, `PostOrders201Response` |
| 3. the property it hangs off, for a nested object | `shipTo:` → `ShipTo` |
| 4. its array, for inline `items:` | `GetOrders200ResponseItem` |
| 5. its address, which is always there and always distinct | |

`displayName:` comes first because it is the only one of them a person wrote as
a *name*. The rest describe where the type is, which is the best available
answer when nobody said what it is.

Rule 4 exists because the alternative is `Items`: the structure's word for the
position rather than anybody's word for the type, wanted by every inline array
in the document, so the second one silently becomes `Items2` — a name that says
nothing and changes when a third arrives.

### Security

`security.py` carries one `SchemeSpec` per `securitySchemes:` entry: which
header the credential goes in, and what precedes it. A `Pass Through` or `x-`
scheme names its own header through `describedBy:`, so a client that always sent
`Authorization: Bearer` would be sending it where the API is not reading.

```python
from bookstore_api import security

client = security.MACHINE_TOKEN.client(base_url=..., token=...)
```

Each module under `api/` carries a `SCHEMES` tuple naming which of them its
operation accepts.

## When the API drifts from the document

A client is generated against a document and then run against a server, and the
two move apart. **A payload never takes the caller down.** A client that raised
on a response mismatch would stop working the first time the API moved, and it
would fail on the whole body rather than on the one property that changed —
including every property that did arrive, which is usually all of them and
usually all the caller wanted.

`tests/test_drift.py` is the executable version of this table.

| the server | the client | where the discrepancy goes |
|---|---|---|
| adds a property | ignores it | nowhere; this is not a discrepancy |
| adds an `enum` value | passes it through | nowhere |
| drops a required property | leaves the attribute `UNSET`, keeps the rest | `Response.mismatches` |
| sends a value that cannot be read | returns no parsed body, keeps `content` | `Response.mismatches` |
| sends the wrong shape entirely | returns no parsed body, keeps `content` | `Response.mismatches` |
| changes a property's type | passes it through | nowhere; this does not validate |
| answers with an undocumented status | returns `None`, or raises `UnexpectedStatus` when asked | |

```python
result = get_books.sync_detailed(client=client)
if not result.matched:
    log.warning('the API has moved: %s', '; '.join(str(one) for one in result.mismatches))
# result.parsed still holds everything that did arrive.
```

A missing property leaves `UNSET`, which is falsy, so `if book.isbn:` does the
right thing without a caller knowing any of this. The annotation still says
`str`, and that is a deliberate unsoundness at exactly one point — a server that
broke its contract. Making every property `str | Unset` would price the normal
case for the benefit of the abnormal one.

The first and third rows are opposite on purpose: an addition is the compatible
direction and a removal is not, which is the axis
[`fastraml compat`](../../docs/16-graph.md) grades a pair of versions on. A
change it calls compatible is one a generated client does not even notice.

### If you would rather it stopped

```python
client = Client(base_url=..., strict=True)
```

`errors.UnexpectedPayload` then names the type and the property. Both it and
`UnexpectedStatus` are `errors.ClientError`, so a caller that only wants to know
"the API did not do what the document said" catches one thing.

## What this does not do

**It states no RAML rule, and it may not.** Every rule ran before the tree
existed; anything this package had to decide for itself about the *language*
would be a gap in the parser (`docs/17-consumers.md` § 2).

Two decisions here that look like rules and are not:

- **Which response a `sync()` call returns** — the lowest documented `2xx`. That
  is a client convention. The detailed variants reach every documented code, and
  an undocumented one raises `UnexpectedStatus` when the client is configured to.
- **Which media type a request body uses** — the first one declared. RAML orders
  them and says nothing about preference.

There are **no `4xx` response classes**, and that absence is deliberate: RAML
states 3-digit codes and nothing else (`docs/08` § 3). A generator modelled on an
OpenAPI generator is exactly where that construct would arrive by analogy.

**It does not validate.** A `pattern:`, a `minimum:` or a `maxItems:` is carried
into the docstring and not into a check. Numeric bounds stay the exact decimal
strings the tree carries and are never divided — the parser is careful not to put
a number through a float, and a client is no place to undo that.

## Working on it

```bash
uv sync --all-extras --dev
uv run ruff check . && uv run ruff format --check . && uv run mypy raml_codegen/ && uv run pytest -q
```

The suite generates a client from `fixtures/sample/api.raml`, compares it against
the golden record in `tests/golden/`, and then runs `ruff`, `mypy --strict` and
`compileall` over what it generated — under the `pyproject.toml` the generator
wrote for it. Regenerate the golden with:

```bash
uv run python tests/regenerate_golden.py
```

Read the diff. A golden that changed without a template or a spelling changing
is a golden that recorded something it should not have.
