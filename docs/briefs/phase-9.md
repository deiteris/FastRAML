# Phase 9 brief — hardening and release

A working brief for a fresh session. Read this, then the documents it names. It
exists so you do not have to re-derive what earlier sessions already settled.

This is the first phase with no conformance work in it. Everything that decides
whether a document parses correctly is done; what is left is whether the parser
is fast enough, safe enough, and pleasant enough to depend on.

## 3. What to build

`docs/15`'s order, which is deliberate: the two things that *change behaviour*
land before the API is frozen.

### 3.1 Benchmarks first

Not because they are urgent but because everything after them is judged against
them, and because a baseline taken after a "small optimisation" measures the
optimisation rather than the parser.

`bench_large`'s 7000-type corpus is **generated by a script in the repo**, not
vendored (`docs/14` § 5), so it can be regenerated at half size to check that the
curve is linear. That is the actual acceptance criterion — within 15 % of linear
— and it needs two sizes, not one.

### 3.2 Depth guards and `re2`

The two hardening items that change behaviour. Reconcile the three ceilings named
in § 1.1 into one story a caller can reason about; a document that trips one
should say which one and what the limit was.

### 3.3 `parse_lenient`

Returns a result carrying both a partial model and the accumulated errors,
instead of raising. The four fail-fast cases stay fail-fast — an unreadable entry
file, a missing or unrecognised RAML header, a non-mapping root, and a fragment
whose kind does not match its context — because none of them leaves anything to
return.

### 3.4 The CLI, the export list, the docs

`docs/13` § 8 for the first. For the second, widen `__all__` to the model classes
a consumer needs for `isinstance`, and fix the `__init__.py` docstring. For the
third, reconcile `docs/01` § 4 against reality: some of those deviations were
argued for in Phase 2 and may have been overtaken.

## 4. Decisions already settled — do not re-litigate

1. **The model may be cyclic, is mutable and unguarded, and one `Raml` is
   single-threaded** (`docs/13` § 7). These are contracts, not defects to fix
   before release.
2. **The `$`-rooted validation path is built eagerly**, and the alternative — a
   list of segments joined on error — is deferred until a benchmark justifies it
   (`docs/10` § 3). This phase produces that benchmark; if it says the paths
   dominate, the change is in scope. If it does not, leave it.
3. **`uniqueItems` switches strategy at 20 items** (`docs/10` § 5.2). Measured
   against go-raml, not guessed.
4. **The union-facet gap stays open.** It is After-v1 item 2 in `docs/15`, and
   the fix has to land in go-raml too — the user's call, already made.

---

## 5. The thing most likely to go wrong

A performance phase invites changes that are correct in isolation and break an
invariant that no benchmark measures. The list in `CLAUDE.md` under "Rules that
look like style but are load-bearing" is exactly the set at risk: node identity,
`__slots__`, the absence of `__eq__`, the identity-keyed overlays, the
no-`deepcopy` rule and the no-`float` rule all read as micro-decisions and all
have a test behind them. Run the full suite, not the benchmark.

## 6. Definition of done

`docs/15` § Phase 9: `bench_large` within 15 % of linear against a half-size
corpus; peak RSS under 400 MB; `mypy --strict` clean; the deviation list in
`docs/01` § 4 matches reality; the skip list contains only Overlays, Extensions
and XSD.

**That last clause is now wrong** and should be amended rather than met: the two
gist-fetching fixtures are skipped by name as suite policy, and the criterion was
written before they were found (`docs/15` § Phase 6's outcome records why).

## 7. Working method

Branch: `git checkout -b phase-9-hardening`. One logical change per commit;
commit any ratchet movement separately from the code that causes it — though this
phase should cause none, and a ratchet change here is a signal to stop and look.

If the code must diverge from a document, **amend the document in the same
commit**, and record what this brief got wrong in a section at its top — every
brief since Phase 5 has needed one.
